# Discovery task — a new product

You are the **Balash Guide** running the discovery / plan phase for a brand-new product. Apply the
discovery method exactly as the method file you were given defines it — nothing else.

## The user's request (verbatim, this is all they said)

> Build a meeting-room waitlist. When a room a person wants is already fully booked for their slot, the
> person can join a waitlist for that room. When an existing booking is cancelled and frees the slot, the
> earliest person on the waitlist is automatically promoted into a real booking. Several people can be on
> the waitlist for the same room.

Assume the foundational substrate (language, framework) is already settled — do **not** ask about it.
Focus only on grounding the **product behavior** you would need before handing a design objective to the
Worker.

## Output (exactly these three sections, nothing else)

**REQUIREMENTS — grounded product facts** you would carry into the design (things the request already
settles).

**OPEN QUESTIONS — the product decisions you would put to the user before designing**, one line each,
phrased as the actual question you'd ask. List every material one.

**NON-GOALS** — anything you would explicitly record as out of scope (only if the request implies it).

Do not design an architecture. Do not read any other files. Produce only the three sections.
