# בלש אישי למעקב קניות: מדריך הפעלה

המוצר הראשון שנבנה על ארגז הכלים של בלש. שולחים לו בוואטסאפ צילום או PDF של קבלות מהסופר ומהמכולת. הוא מאשר מה קרא, מתריע כשיש אי התאמה בחשבון המכולת, ושולח בתחילת כל חודש סיכום עם גרפים.

## מה הוא עושה

- **קורא כל מסמך קנייה:** קבלה מהסופר, פתק מהמכולת, קבלה על תשלום, או פירוט חשבון.
- **מאשר מיד מה נקלט:** חנות, תאריך, סכום, מספר פריטים, היתרה בחשבון, ומה לא נקרא בוודאות.
- **בודק את חשבון המכולת:** היתרה הקודמת בכל פתק חייבת להתאים ליתרה אחרי הפתק הקודם, בניכוי תשלומים שרשמת. כשהיתרה קפצה בלי פתק שמסביר את זה, מגיעה התראה. ייתכן שמישהו נרשם על החשבון שלך, או שפתק לא נשלח.
- **בודק גם את החשבון של הפתק עצמו:** יתרה קודמת ועוד הקנייה פחות התשלום חייבים לתת את היתרה החדשה המודפסת.
- **מצליב פירוט חשבון מהמכולת:** כל חיוב בפירוט צריך להתאים לפתק ששלחת.
- **מסכם כל חודש:** סה"כ, השוואה לחודש הקודם, פילוח לפי חנות, קטגוריה ושבוע, המוצרים היקרים, שינויי מחיר של אותו מוצר באותה חנות, ויתרות. כולל שלושה גרפים.

## פקודות בוואטסאפ

| שולחים | מקבלים |
|---|---|
| תמונה או PDF | אישור מה נקלט, והתראה אם יש אי התאמה |
| `דוח` | סיכום החודש הנוכחי |
| `דוח 9` או `דוח 2026-09` | סיכום של חודש מסוים |
| `יתרה` | היתרה בכל חשבון מכולת |
| `שילמתי 250 מכולת יוסי` | רישום תשלום על החשבון |
| כל דבר אחר | הסבר קצר |

## איך זה בנוי

הכול רץ כצינורות של בלוקים, בדיוק לפי מסמך התכנון. הצינורות נמצאים בתיקייה `config/pipelines`, ואפשר לקרוא אותם כמו רשימה.

| בלוק | סוג | מה הוא עושה |
|---|---|---|
| `receipt_inbox` | מאוחד | מהודעת וואטסאפ לרשומות: רק ממספרים מאושרים, הורדת הקובץ, שמירה, קריאה. לא יותר מזה |
| &nbsp;&nbsp;`raw_store` | תוכנה | בתוך `receipt_inbox`: שומר כל קובץ פעם אחת ולתמיד, ומזהה קובץ שנשלח שוב |
| &nbsp;&nbsp;`receipt_to_records` | הרנס | בתוך `receipt_inbox`: ממיר מסמך לרשומות לפי סכמה קבועה. מעתיק, לא מחשב |
| `purchase_ledger` | תוכנה | שומר, מזהה את החנות לפי כינויים, ומדלג על קבלה כפולה |
| `categorize_items` | הרנס | מסווג מוצר חדש לקטגוריה. כל מוצר נשלח למודל פעם אחת בלבד |
| `tab_continuity` | תוכנה | בודק רצף בין פתקים בחשבון המכולת |
| `statement_reconcile` | תוכנה | מצליב פירוט חשבון מול הפתקים |
| `payment_from_text` | תוכנה | רושם תשלום מהודעה |
| `monthly_stats` | תוכנה | מחשב את כל המדדים החודשיים |
| `stats_charts` | תוכנה | מצייר את הגרפים |
| `receipt_ack`, `finding_messages`, `monthly_report_text`, `balances_text`, `payment_ack` | תוכנה | מנסחים את ההודעות |
| `notify` | תוכנה | שולח לוואטסאפ או למסוף |

**המודל עושה רק שני דברים:** קורא מסמכים וממיין מוצרים. כל חישוב, השוואה והתראה הם קוד. אחרי המודל, קוד בודק שהסכומים המודפסים מסתדרים זה עם זה. מה שלא מסתדר מסומן כלא ודאי ומדווח לך, במקום להפוך בשקט לנתון.

**כל תשובה של המודל נשמרת** לפי תוכן הקובץ וגרסת ההנחיות. הרצה חוזרת על אותה קבלה לא עולה כסף ונותנת אותה תוצאה.

## הרצה מקומית, בלי וואטסאפ

כך בודקים את קריאת הקבלות לפני שמחברים וואטסאפ.

```bash
pip install -e ".[dev]"
balash init                       # יוצר config/instance.yaml
export ANTHROPIC_API_KEY=...      # מפתח ל-Claude API
balash ingest ~/receipts/*.jpg    # קורא קבלות ומדפיס מה נקלט
balash pay 250 "מכולת יוסי"       # רושם תשלום
balash balances                   # יתרות
balash report --month 2026-09     # סיכום חודשי, הגרפים נשמרים ב-data/reports
python -m pytest                  # הבדיקות, בלי מפתח ובלי רשת
```

לפני הכול כדאי לערוך את `config/instance.yaml`: את שמות המכולות שלך ואת הכינויים שלהן, ואת החנויות שבהן יש לך חשבון.

## חיבור לוואטסאפ

הצעדים בממשק של Meta משתנים מדי פעם. זה הסדר הנכון, והשמות עשויים להיות מעט שונים.

1. **אפליקציה ב-Meta.** נכנסים ל-developers.facebook.com, יוצרים אפליקציה מסוג Business, ומוסיפים לה את המוצר WhatsApp.
2. **מספר בדיקה.** בעמוד ההגדרות של WhatsApp מופיע מספר בדיקה חינמי. מעתיקים את ה-Phone number ID ומפיקים access token. הטוקן הזמני תקף ליום. לשימוש קבוע יוצרים System User בהגדרות העסק ומפיקים לו טוקן קבוע.
3. **המספר שלך.** מוסיפים את מספר הטלפון שלך לרשימת הנמענים של מספר הבדיקה ומאמתים אותו בקוד.
4. **App secret.** נמצא בהגדרות הבסיסיות של האפליקציה. הוא משמש לאימות שכל הודעה באמת הגיעה מ-Meta.
5. **כתובת ציבורית.** מריצים `balash serve` על מחשב שדולק, ופותחים אליו מנהרה, למשל:

   ```bash
   cloudflared tunnel --url http://localhost:8000
   ```

6. **Webhook.** בהגדרות ה-Webhook של WhatsApp מזינים את הכתובת עם `/webhook` בסוף, ואת ה-verify token שבחרת. אחר כך נרשמים לשדה `messages`.
7. **משתני סביבה.** לפני `balash serve`:

   ```bash
   export ANTHROPIC_API_KEY=...
   export BALASH_OWNER_NUMBER=9725XXXXXXXX       # המספר שלך, ספרות בלבד
   export WHATSAPP_PHONE_NUMBER_ID=...
   export WHATSAPP_ACCESS_TOKEN=...
   export WHATSAPP_APP_SECRET=...
   export WHATSAPP_VERIFY_TOKEN=מילה-שבחרת
   ```

8. **בדיקה.** שולחים `עזרה` למספר הבדיקה. אמורה לחזור הודעת הסבר. אחר כך שולחים צילום של קבלה.

**מגבלת 24 השעות של וואטסאפ.** עסק יכול לשלוח הודעה חופשית רק תוך 24 שעות מההודעה האחרונה שלך. אם הסיכום החודשי נוצר מחוץ לחלון, הוא נשמר ונשלח ברגע שתכתוב משהו. אפשר גם פשוט לשלוח `דוח`.

**רק מספרים מאושרים מטופלים.** ברירת המחדל היא רשימת `owners` בקובץ ההגדרות. לבלוק `receipt_inbox` אפשר לתת רשימה משלו בפרמטר `allowed_senders` בקובץ הצינור. תמונה ממספר שלא ברשימה לא מורדת, לא נשלחת למודל ולא מקבלת תשובה.

## מה עוד לא נבדק

- **קריאת קבלות אמיתיות לא נבדקה עדיין,** כי לא היה מפתח API בסביבת הפיתוח. צורת הקריאה ל-API נבדקה מול שרת מדומה, והצינור כולו נבדק עם מודל מדומה. הצעד הראשון שלך הוא `balash ingest` על עשר קבלות אמיתיות, ובדיקה של מה נקרא.
- **החיבור לוואטסאפ נבדק מול לקוח מדומה בלבד.**
- **פתקים בכתב יד** הם המקרה הקשה ביותר לקריאה. כדאי לבדוק כמה מהם מוקדם.

## מה לשפר אחרי ניסיון ראשון

1. **לאסוף עשר קבלות אמיתיות לכל סוג** עם התוצאה הנכונה, ולהפוך אותן לסט בדיקה של בלוק ההרנס.
2. **למדוד שיעור "לא ודאי"** לכל סוג מסמך, ולשפר את ההנחיות בקובץ `prompt.md` של הבלוק לפי מה שחוזר.
3. **תיקון ידני בוואטסאפ,** למשל "הסכום הנכון 243.50", כדי שתיקונים יחזרו כדוגמאות להנחיות.
